# 记录官与检索 · 演示参考示例

> 用途：比赛演示与自测时照着输入，不用临场编数据。
> 前提：落地页点「先看示例」，写入 6 条示例战绩（全部就绪，简历草稿默认已选 6 条，预览仍显示「1 页内」）。
> 下面每一条结果都是本机代码实测，不是设想：JD 走 `parsePastedJd` → `matchJob` → `qualifyJob`，记录官走 `runAgent`。
> 文中三家公司是**自拟演示岗位**，不对应任何真实招聘；页面上仍写「以官网为准」。
> 本文件只管 JD 匹配与记录官；其余四个面与数据闭环的走查清单见 `docs/demo-sample-data.md`。

## 〇、先说清两条路线

| 路线 | 触发 | 实测表现 |
| --- | --- | --- |
| 本机规则（默认，不填 Key、断网也能跑） | 顶栏不填模型接入 | 记录官回复里明说 `未接入模型 已按本机规则拆成四段` |
| 模型主路（BYOK） | 顶栏灵动岛 →「设置」→ 模型接入，填自己的 API-KEY | 四段由模型拆，数字与证据仍受原文校验，对不上就丢 |

Key 只写本机 `localStorage`，不进 IndexedDB、不进导出 JSON、不进模型输入，「清除本机数据」一并删除。演示时先跑规则路线就够，填 Key 只用来对比一次。

接 Key 后多一层自动判断：粘进来的长文本（≥ 40 字）先由模型判「这是岗位原文还是口述经历」，它只做分类，不改写任何内容；拆 JD 与拆四段仍走本机 `parsePastedJd` 与本机规则。模型超时、报错或自己标 low 时返回空值，直接落回下面的本机关键词链，行为与不填 Key 一致。不填 Key 时这一层不参与，主流程不受影响。

## 一、三张可粘贴 JD（覆盖现实可达三档）

入口一：征召页 →「粘贴 JD 匹配」。填完选填项再粘原文，点「解析并匹配」，卡片会存进本机岗位库（刷新不丢，最多 60 张；公司、岗位名、要求清单三项全同才算重贴，只替换不堆叠）。

入口二：记录官。打开记录官，整段 JD 直接粘进输入框回车，出现「岗位草稿」卡 → 点「存进本机岗位库」，同样进候选池、同样参与排序。公司、岗位名、城市没填时写「公司未填」，不猜；第一行 4–30 字会被当作岗位名。

实测（示例数据 + 下面这段）：

```text
字节跳动 推荐算法实习生
岗位职责：
1. 负责推荐系统排序模型的设计与迭代
2. 负责特征工程与离线评估
任职要求：
1. 熟悉 Python 与 SQL
2. 有机器学习项目经验
3. 每周到岗 4 天 实习 3 个月以上
```

回复 `已按岗位 JD 处理 公司未填 岗位 字节跳动 推荐算法实习生` / `拆出 3 条要求 识别 3 个技能` / `对照选进简历的 6 条战绩 24 分 缺口较大 命中 0/2 差得多`，草稿卡列公司、岗位、类型、要求与缺口，确认后回 `已存进本机岗位库「字节跳动 推荐算法实习生」 24 分 差得多 去征召会和演示卡一起排序`，征召页出现一张标「本机岗位库」的卡。

同一段话换成口述经历（如「做了一个校园二手交易小程序 原来同学们在群里刷屏找书 我用微信小程序加云开发重写了发布和检索流程 负责数据库设计和 6 张表 上线两个月成交 300 单」）会出「经历草稿」，不会被当成 JD：本机规则看小标题与条目式短句，带「我负责 / 我用」的主语归口述。

### 1 号 · 现在就能投

岗位名称 `前端开发实习生` 公司 `杭州知路教育科技有限公司` 城市 `杭州` 类型 `实习`

```text
任职要求：
- 本科及以上在读，计算机相关专业优先
- 熟悉 React 与 TypeScript，能独立完成页面开发
- 了解前端性能优化，会用 Chrome 调试工具定位瓶颈
- 了解 Git 分支协作，参与每周代码评审
- 每周到岗 4 天以上，连续实习 3 个月
```

实测：`94 分 · 够格 · 高匹配 · 命中 3/3 · 缺口 0 · 技能 4/4`。三条命中全部回指「前端开发实习生」那条战绩的原文，例如
`熟悉 React 与 TypeScript…` → 「在 React + TypeScript 页面里做性能优化：用 Chrome Performance 定位瓶颈，拆分长列表、图片懒加载、把首屏接口从串行改成并行」。

说法：小公司的岗位只要粘进来，就能和自己做过的事逐条对上，够格就是够格，不用先够大厂。

### 2 号 · 补一条证据就能投

岗位名称 `数据分析实习生` 公司 `某市增长数据服务有限公司` 城市 `未填写` 类型 `实习`

```text
任职要求：
- 本科及以上在读，大二及以上
- 熟悉 Python 数据处理，能自己完成清洗与画图
- 有数学建模或统计分析经历，能讲清模型选择的原因
- 能把分析结论写成报告，说明指标定义与口径
- 掌握 SQL 基础查询与多表连接
```

说法：差的就是一个能拿出来的证据，不是方向选错了。

## 二、现场把 3 号从差得多变成够格

示例数据里没有嵌入式战绩，但课表和作业里有「嵌入式系统综合设计实训」和「使用外部中断实现指示灯交替闪烁」，正好拿来记成一条。

1. 打开记录官，把下面这段**一整段贴进去**——不用分号，不用「标题：」这种标签，想到什么说什么，句与句之间空一格：

```text
记一条经历 嵌入式外部中断控制指示灯实验 原来的指示灯只能靠手动按键切换 演示的时候容易出错 我们用 C 语言配置外部中断和定时器 让两个指示灯交替闪烁 我负责中断初始化和板级联调 实验报告最后评为优秀
```

实测回复（刚粘完 3 号，本机岗位库里已有这张卡）：

```text
已自动分成四段 类型 课程设计
未接入模型 已按本机规则拆成四段
对照「一家做汽车零部件测试的小厂 嵌入式软件实习生」这条已覆盖全部可匹配要求
离简历就绪还差 证据或量化数据
```

岗位库空着时第三行改说最接近的演示卡，实测为 `对照「阿里巴巴 算法实习生」这条还差 3 项要求` + `- 熟悉 Python，掌握机器学习基础 这条里没写到` + `- 了解 PyTorch 或 TensorFlow 之一 这条里没写到`。这两行就是**对照岗位库的补全提示**：记录官拿这条草稿去比对本机岗位库里最接近的那张卡，直接说出差在哪，不用你自己翻。

草稿实测：标题 `嵌入式外部中断控制指示灯实验`、类型 `课程设计`、技能 `嵌入式 C`。展开「查看四段式」逐字对得上：

| 段 | 实测内容 |
| --- | --- |
| 问题 | 原来的指示灯只能靠手动按键切换，演示的时候容易出错 |
| 方法 | 我们用 C 语言配置外部中断和定时器 让两个指示灯交替闪烁 |
| 我的贡献 | 我负责中断初始化和板级联调 |
| 结果 | 实验报告 最后评为优秀 |

2. 点「确认写入征途」→ 实测回复 `已写入征途「嵌入式外部中断控制指示灯实验」 离简历就绪还差 证据或量化数据 可以去经历页补`，征途卡片角标 `品质 3/4 差 证据或量化数据`，量化数据一栏写 `原文未提供量化数据`。四段齐但缺数字，第 4 格不亮，这是数据铁律 7。
3. 在征途点「编辑」→「+ 添加量化数据」→ 名称 `切换间隔` 数值 `200 毫秒` → 保存 → 实测角标 `品质 4/4`，简历草稿自动从 6 条变 `已选 7 条`，新这条已勾上。
4. 回征召选中 3 号 → 实测 `91 分 · 够格 · 高匹配 · 命中 2/2 · 缺口 0`，两条命中分别回指「我们用 C 语言配置外部中断和定时器 让两个指示灯交替闪烁」（经历原文，技能 C）和「技能标签：嵌入式」。

说法：项目不是推荐引擎，是把「差哪一条」记下来、补完就翻盘的账本。

## 四、演示顺序（约 90 秒）

1. 粘 1 号 → 94 分够格，说明小厂岗位进了候选池且刷新不丢
2. 记录官问 `我有哪些关于性能优化的经历` → 原句回指，说明检索跑在自己的战绩上、不调模型、断网可跑
3. 粘 3 号 → 15 分差得多
4. 一整段口述记一条 → 回复当场说出四段和这张 JD 的缺口 → 确认入库 → 品质 3/4 → 补 `200 毫秒` → 4/4 已就绪
5. 回征召看 3 号 → 91 分够格，命中的是新战绩原文

## 五、别在演示里踩的坑

- 口述时句与句之间空一格最稳，空格就是本机规则的分隔符；段子里带数字（如「每 200 毫秒」）会直接抽成一条量化，跳过第 2 步的「品质 3/4」，讲铁律 7 时要用上面这段不带数字的版本
- 检索词要具体。「设计稿」这种宽词实测返回 4 条，其中「数据库课程设计验收通过…」属于弱相关（bigram 命中「设计」二字），换成「性能优化」「数据库」「论文」就干净
- 岗位「职能方向」归类不稳：前端 JD 会被判成 `设计` 或 `职能`，别在筛选器上强调这一维
- 本机岗位库没有单张删除入口，要清干净用灵动岛里的「清除本机数据」（会连示例数据一起清）
- 记录官粘 JD 与征召页走同一条解析和去重：同一段 JD 在两处各粘一次，本机岗位库只保留一张
- 岗位名称留空时取 JD 第一行当标题，第一行得是 4–30 字才生效；「任职要求：」这种会被当成标题，演示时把岗位名称填上
- 匹配只认**已选进简历草稿**的战绩：未勾选的战绩即使就绪也只算「还没进简历」，卡片会写「勾选后可提升命中」并给「去简历勾选」入口
- 粘贴 JD 不计留痕、不点绿格，也不进简历文案；简历、打印页、导出 JSON 里不会出现游戏化措辞
