# 学径 StudyTrack · 产品规格 v0.1

> 状态：方向已确认，待规则同步与实现排期 · 2026-10-31
> 范围：信息架构、今日页、记录官、账本、悬赏、日历、演示脚本
> 关系：本文件取代 `docs/plan.md` 中旧的「六个并列模块」信息架构、M1.3 今日仪表盘、以及 Won't 中的「AI 聊天窗」；不改动数据铁律与合规红线。与 `.qoder/rules/00-core.md` 冲突处，以本文件为准；规则已同步。

## 0. 一句话

**每天 30 秒，把大学四年变成一份可验证的履历。**

原来的「学习 + 经历聚合工作台」是功能清单，不是承诺。真正的敌人不是别的学习 App，是「毕业时想不起自己做过什么」。

## 2. 定位与产品模型

### 2.1 五层模型

| 层 | 内容 | 说明 |
|---|---|---|
| 输入 | 课表、作业、对话、截图 | 用户几乎不用手填 |
| 账本 | 经历、证据、技能、时间线 | 核心资产 |
| 输出 | 简历、作品集、学期战报 | 账本的导出格式 |
| 用途 | 机会、悬赏、匹配 | 账本的用途 |
| 节奏 | 今日、绿格、日结 | 让积累每天可见 |

一句话：**课表作业是输入，经历是账本，简历是导出格式，机会是账本的用途，今日是节奏。**

### 2.2 核心循环

打开 → 看见变化 → 30 秒留一件事 → 立刻看到它变成资产 → 下次有理由回来。

任何功能都要回答：它服务这个循环的哪一步？不服务的只能是佐料，不能当主菜。

### 2.3 留存目标

- 每次打开都有用；
- 每周有 3–4 次打开的理由；
- 每学期有一个「不回不可」的节点（选课、期末、投递季）。

不做资讯 App：天气只做一行，新闻后置，聊天是输入方式而不是目的地。留存来自「自己的账本在变厚」，不是「我们生产了更多内容」。

## 3. 信息架构

### 3.1 一级导航

| 一级 | 页面 | 说明 |
|---|---|---|
| 今日 | TodayPage 重做 | 判词、昨日结算、今日委托、留痕、情报、回声、绿格 |
| 账本 | ExperiencesPage 演进 | 战绩、证据、时间线、热力图、碎片收件箱、就绪度、出征 |
| 悬赏 | OpportunitiesPage | 6 个官方入口 + 人工岗位卡 + 粘贴 JD + 匹配 |
| 工具箱 | 新 Hub | 课表、作业、简历、日历、存档、关于 |

- 六页代码不删，只重新分组。
- 桌面端工具箱展开子项，仍是一步可达；移动端底部四个一级 + 记录官。
- 保留今日默认入口、任何页面一步切走、不锁功能、不强制顺序。
- 作品集放在账本内；关于、存档放在工具箱内。

### 3.2 半世界命名

| 功能 | 一级/页面名 | 页面内称呼 | 备注 |
|---|---|---|---|
| 今日 | 今日 | 今日判词、昨日结算、今日委托、回声 | 功能名 |
| 账本 | 账本 | 战绩、战绩册、出征、留痕 | 账本本身就是比喻，保留 |
| 悬赏 | 悬赏 | 悬赏榜、官方入口、岗位卡 | 最贴世界观 |
| 工具箱 | 工具箱 | 课表、作业、简历、日历、存档 | 功能名 |
| Agent | 记录官 | 记录官 | 全局入口 |
| 绿格 | 留痕 | 留痕 / 足迹 | 账本内用热力图 |

## 4. 今日页

### 4.1 三个问题

今日页每天只回答：**今天要面对什么 / 今天能留下什么 / 我离目标近了吗。**

### 4.2 页面结构

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 今日判词 | 日期、周次、天气一行 + 一句判词；判词必须引用真实数据 | Profile + 课表 + DDL + 日历 |
| 昨日结算 | 完成了什么、新增了什么、连续第几天；当天首次打开置顶，可收起 | LedgerEvent |
| 今日委托 | 最多 3 件：最近 DDL、待确认记录、agent 建议；一键完成 | Assignment + Experience + Agent |
| 留痕入口 | 「今天有什么值得留下的？」说一句 / 拍一张 / 选一个；默认带「今日一问」 | Note / Experience |
| 今日情报 | 1–3 条竞赛、考试、校内节点；每条一句 + 为什么与你有关 + 动作 | CalendarItem |
| 回声 | 旧记录、未完成的事、一年前的今天；每天最多 1 条 | LedgerEvent + Experience |
| 本周绿格 | 7 格 + 档案厚度（战绩数、证据数、就绪度） | LedgerEvent + Experience + Resume |

砍掉三格统计条、整周 DDL 网格、独立经历面板——不是删功能，是换位置。完整周视图、全部 DDL、时间线回到各自页面。

### 4.3 规则与细节

- **一天按本地 04:00 切日**，避免熬夜把记录算到第二天。
- **今日判词**用模板拼真实数据；可选一句 LLM 文案，失败回退模板。没有数据时只问一个问题，不写空泛励志句。
- **昨日结算**只写事实，最多 3 行；没有记录就中性显示「昨天没有留下记录，今天补一条也算」，不指责。
- **今日委托**只放可产生结果的动作；上课不设勾选，课程信息放在判词和课表入口。
- **留痕**默认产出 Note，信息足够时才提议升级为 Experience；所有 AI 推断带 `confidence`，`low` 标黄可改。
- **今日情报**没有相关项就整块隐藏，不拿通用新闻填充；每条必须显示来源与核对日期。
- **回声**必须具体、有依据；禁止「我想你了」式空话，禁止断签羞辱。
- **绿格**点击打开当天日志；今天只展示本周 7 格，全年热力图在账本。
- 页面模式：学期内 / 考试周 / 假期 / 投递季；假期不硬塞课表，改推悬赏和补记录。

### 4.4 空态

- 没有 Profile：今日页内联三步对话，不跳转注册页。
- 没有课表：展示留痕入口 + 2–3 条示例情报 + 「导入课表后更准」。
- 没有任何数据：保留「先逛示例」；示例数据明确标注。
- 解析/请求失败：落到手动填、示例数据或上一步结果，禁止空白页和无限 loading。

## 5. 记录官（Agent）

### 5.1 定位

记录官不是开放域聊天机器人，是一个**会写账、查账、解读、记忆**的助手。聊天只是输入方式，不是产品目的地。

### 5.2 五个职能

| 职能 | 做什么 | 边界 |
|---|---|---|
| 建档 | 三步对话 → Profile + 第一段战绩草稿 | 每步可跳过，不强迫填写 |
| 写账 | 把一句话/截图整理成 Note 或 Experience | 写入前必须确认 |
| 查账 | 检索经历、DDL、日历、目标 | 用结构化查询 + minisearch |
| 解读 | 粘贴 JD/情报 → 命中与缺口 | 命中必须带 experienceId + 原文引用 |
| 记忆 | 回声、未完成的事、周年记录 | 必须有数据依据，不卖萌 |

### 5.3 入口与交互

- 今日页常驻输入条：「说点什么，我帮你记」。
- 其他页面用侧栏/悬浮按钮打开记录官。
- 不做第七个导航 tab。
- 一次只问一个问题；可跳过、可换一个；不连续追问。
- 所有写操作先出「将要保存的草稿」，用户确认后才落库。
- 语气：短、具体、不奉承、不催促；失败时给下一步，不卖惨。

### 5.4 记忆与成本

- 记忆来自结构化日志：最近记录、长期未更新的经历、临近截止、一年前的今天、目标进度。
- 不上向量库、不调 embedding；文本检索复用 minisearch。
- 日结/周结/情报按天缓存；不要每次打开都调模型。
- 日常摘要优先模板，LLM 只补一句「判词」或「建议」。
- 失败回退模板或手动，不阻塞页面。

### 5.5 成功指标

不看聊了多少句，看**每次对话产出了多少条可保存的记录**，以及「对话 → 保存」的转化率。

## 6. 冷启动

1. 专业 + 年级（两个选择，可跳过）
2. 目标（实习 / 考研 / 保研 / 出国 / 还不确定，可跳过）
3. 最近在忙什么（一句话，可跳过）

完成后立刻给四样东西：

- 个性化今日；
- 第一段战绩草稿；
- 一条匹配的悬赏/情报；
- 第一格绿。

原则：**先给，再要。** 每次索取数据都同时给回报；课表导入放到工具箱，在收益明确时再请求（「导入后每天告诉你几点出门、下周几门课结课」）。

## 7. 数据模型

### 7.1 复用现有模型

`TimetableData`、`AssignmentData`、`ExperienceData`、`ResumeData`、`ResumeSnapshot`、`JobPosting`、`Channel`、`JobMatch` 均复用。`JobPosting` 已有 `sourceKind`、`sourceUrl`、`collectedAt`、`verifiedAt`，人工岗位卡直接使用。

### 7.2 新增模型

```ts
type Grade = "大一" | "大二" | "大三" | "大四" | "研究生" | "其他";
type Goal = "intern" | "postgrad" | "abroad" | "civil" | "undecided";

interface Profile {
  id: "me";
  grade: Grade;
  major: string;
  school?: string;
  goal: Goal;
  targetRoles: string[];
  skills: string[];
  interests: string[];
  onboardedAt?: string;
  lastExportedAt?: string;
  updatedAt: string;
}

type LedgerEventType =
  | "assignment_done"
  | "experience_added"
  | "experience_updated"
  | "evidence_added"
  | "note_added"
  | "resume_generated"
  | "match_run";

interface LedgerEvent {
  id: string;
  date: string; // 本地 YYYY-MM-DD，04:00 切日
  type: LedgerEventType;
  refId?: string;
  title: string;
  detail?: string;
  createdAt: string;
  revokedAt?: string;
}

interface Note {
  id: string;
  text: string;
  createdAt: string;
  source: "text" | "image" | "agent";
  status: "inbox" | "promoted" | "archived";
  linkedExperienceId?: string;
  tags: string[];
  confidence: Confidence;
}

type CalendarCategory = "contest" | "exam" | "campus";

interface CalendarItem {
  id: string;
  title: string;
  category: CalendarCategory;
  organizer?: string;
  fitGrades: number[]; // 1-4
  fitMajors?: string[];
  start?: string;
  deadline?: string;
  sourceName: string;
  sourceUrl?: string;
  sourceType: "official" | "sample" | "personal";
  verifiedAt?: string;
  note?: string;
}

interface AgentAction {
  id: string;
  type:
    | "create_experience"
    | "update_experience"
    | "add_note"
    | "open_calendar"
    | "match_job";
  status: "proposed" | "applied" | "dismissed";
  refId?: string;
}

interface AgentMessage {
  id: string;
  role: "user" | "agent";
  text: string;
  createdAt: string;
  actions?: AgentAction[];
  linkedRecordIds?: string[];
}
```

### 7.3 日志规则

- 一次用户动作只产生一条 `LedgerEvent`，避免重复计数。
- 新增经历（含证据）记 `experience_added`；给已有经历补证据记 `evidence_added`；纯文案修改记 `experience_updated`。
- 计入绿格：`assignment_done`、`experience_added`、`evidence_added`、`note_added`、`resume_generated`。
- 不计入绿格：`experience_updated`、`match_run`、纯打开、纯打卡、删除。
- 同一天多条 `note_added` 只算一次绿格强度。
- 撤销作业完成时回滚对应事件；删除经历时给关联事件写 `revokedAt`，不产生新的正向事件。
- 绿格强度最多 3 级，避免刷量。

### 7.4 存储与迁移

新增 IndexedDB key：

- `studytrack:v1:profile`
- `studytrack:v1:ledger`
- `studytrack:v1:notes`
- `studytrack:v1:agent`

要求：

- `clearLocalData` 覆盖所有现有与新增 key。
- 导出/导入包含：Profile、Timetable、Assignments、Experiences、Resume、Snapshots、Ledger、Notes、AgentMessages。
- 导入用 zod 校验；失败提示原因，不覆盖现有数据。
- `store` 仍是唯一读写 IndexedDB 的地方；`pages` 不直接访问 IDB。

## 8. 日历

### 8.1 数据与位置

- 数据文件：`data/calendar.json`（构建时导入或放公共静态目录）。
- 数量：首版 15 条（竞赛 6 / 考试 4 / 校内 5）；日历页叠加作业 DDL，避免视觉上空。
- 三个类别：`contest` 竞赛、`exam` 考试报名、`campus` 校内节点。
- 完整日历页：工具箱 → 日历；今日只显示 1–3 条。
- 视图：桌面月视图 + 列表；移动端列表优先；支持类别、年级、专业筛选。

### 8.2 首版内容

- 竞赛：计算机设计大赛、数学建模、蓝桥杯、挑战杯、互联网+、智能车/机器人等。
- 考试：四六级、计算机等级、普通话、考研报名、雅思/托福等。
- 校内：选课、校历、期中/期末、实验室招新、讲座、奖学金、创新学分等。
- 校内节点先用「示例大学」占位，允许用户修改；后续可替换为学校公开校历。

### 8.3 来源规则

- `sourceType: "official"` 必须有 `sourceUrl` 和 `verifiedAt`；没有就标 `sample`。
- 过期项隐藏或标灰，不删除，避免历史记录丢失。
- 首版人工维护，每周核对一次；不做运行时爬取。
- 不允许编造日期；不确定写「待核对」，不冒充官方。
- 新闻后置：等真实 RSS/API 源确定后再接，不用模型凭记忆生成新闻。

### 9.2 人工岗位卡

- 首版 6–12 张，演示用 3 张。
- 只写：公司、岗位、城市、类型、方向、3–5 条要求摘要、技能标签、适合年级、截止时间、官方链接、核对日期。
- 不复制 JD 正文，不承诺「实时更新」。
- 演示卡标注「演示数据」，不冒充当前在招岗位。
- 大一视角：不直接推「现在投」，显示「还有 2 年」和「先积累什么」；大三视角：显示匹配与缺口。

### 9.3 匹配

沿用现有 BM25 + 本地规则：

- 经历标签 + 技能 + 课程 + 年级 ⟷ 岗位要求；
- `Match.hits` 每条必须带 `experienceId` + 原文引用；
- 缺口给具体建议，不输出没有来源的命中；
- LLM 只负责解释和措辞，不负责编造经历。

## 10. 激励

### 10.1 绿格

- 含义是「你留下了东西」，不是「你来了」。
- 只统计产生结果的动作；删除、纯打开、纯打卡不算。
- 不惩罚断签：空格就是空格，没有红叉、没有掉级；连续记录给称号，断了显示「重新开始第 1 天」。
- 目标用「本周 4/7」，不用「每天必须」。
- 今日显示本周 7 格，账本显示全年热力图；点击格子打开当天日志。

### 10.2 四层奖励

| 时间尺度 | 反馈 |
|---|---|
| 秒级 | 保存后立刻「档案 +1 / 匹配 3 个悬赏 / 证据 +1」 |
| 日级 | 绿格、本周进度、昨日结算 |
| 周级 | 周报、简历就绪度 |
| 学期级 | 学期战报、称号/等级 |

多巴胺来自相关性和复利，不是金币。积分、抽卡、排行榜先不做，容易空心化。

### 10.3 档案厚度

首版用确定性公式，仅作方向指示，不对外承诺：

- 基本信息 20%
- 至少 3 条经历 30%
- 经历有证据 30%
- 技能/目标匹配 20%

就绪度是罗盘，不是评分；不做断签羞辱、不做虚假紧迫感、不做红点轰炸。

## 11. 演示

### 11.1 演示模式

- 用 `?demo=1` 或显式开关进入；种子数据 + 模拟日期。
- 所有演示岗位卡、日历项标注「演示数据」。
- 不修改真实用户数据；退出演示恢复本机数据。
- 明确告知评审：这是演示数据，不是实时岗位。

### 11.2 三分钟脚本

| 时间 | 画面 | 动作 |
|---|---|---|
| 0:00–0:30 | 首次进入 | 记录官问三句：专业年级、目标、最近在忙什么；每步可跳过 |
| 0:30–1:00 | 建档 | 答「人工智能、大一、还不确定、刚做了手写数字识别」→ 画像 + 第一段战绩草稿 |
| 1:00–1:30 | 今日点亮 | 个性化判词 + 一条竞赛情报 + 留痕入口 + 第一格绿 |
| 1:30–2:00 | 留痕 | 补一句「准确率 92%→96%，加了数据增强」→ 战绩补证据，绿格加深 |
| 2:00–2:30 | 日历 + 悬赏 | 竞赛截止提醒；大疆/华为/字节岗位卡 → 匹配命中与缺口 |
| 2:30–2:55 | 闪前三年后 | 6 条战绩、12 条证据、热力图、就绪度 78% → 一键出征 A4 简历 |
| 2:55–3:00 | 收尾 | 「你从大一开始的每一件事，都在这里。」 |

第一段经历：手写数字识别课程项目；第一条竞赛：计算机设计大赛或数学建模；岗位方向：AI 算法、数据分析、AI 产品。

## 12. 规则变更与合规

### 12.1 需要同步的规则

- `.qoder/rules/00-core.md`：六个并列模块 → 四个面 + 记录官；保留今日默认入口、任何页面一步切走。

- 不改：纯静态、无账号、无服务端数据库、当前零爬虫、Key 不进前端、PDF 浏览器打印、依赖白名单。

### 12.2 数据与隐私

- Profile 不收集姓名、学号、身份证、手机号；这些只在打印简历的 `ResumeBasics` 中出现。
- 发给模型的内容不含身份信息；只发完成当前任务所需的片段。
- About 页更新：说明新增的 Profile、Ledger、Notes、AgentMessages 存哪里、发给模型什么、如何一键清除。
- 导出/导入必须覆盖全部数据；「清除本机数据」必须清干净。

### 12.3 关于爬取

- 当前仍按零爬虫执行：六家公司只做官方入口 + 人工岗位卡。
- 如后续要自动采集，需要单独确认，并满足：白名单域名、构建期采集、robots.txt/ToS 检查、不登录、不绕反爬、限速、缓存、标注来源与采集时间。
- 不做招聘站/校招官网的运行时抓取；不做代投。
